# Install

Prusa Telemetry supports three install paths. The jar path is the easiest way
to run the application; it only needs Java at runtime.

## Jar Download

Use this for an operator install without Clojure, npm, or a source checkout.

```bash
curl -L -o prusa-telemetry.jar \
  https://github.com/aeonik/prusa_telemetry/releases/latest/download/prusa-telemetry.jar
curl -L -o prusa-telemetry.jar.sha256 \
  https://github.com/aeonik/prusa_telemetry/releases/latest/download/prusa-telemetry.jar.sha256
sha256sum -c prusa-telemetry.jar.sha256
java -jar prusa-telemetry.jar
```

Open:

```text
http://localhost:8080
```

For an always-on service, place the jar in `/opt/prusa-telemetry/` and follow
[deploy-systemd.md](deploy-systemd.md).

## Source Production Run

Use this when Clojure is installed on the target machine but you do not need a
managed dev REPL. Source builds also need Node/npm because the Reagent frontend
uses React from npm while compiling browser assets.

```bash
cp config/prusa-telemetry.edn.example config/prusa-telemetry.edn
clojure -T:build release
clojure -M:prod:run-web
```

Open:

```text
http://localhost:8080
```

## Source Jar Build

Use this when you want to produce the same standalone jar generated by CI.

```bash
clojure -T:build release
```

Artifacts:

```text
target/prusa-telemetry.jar
target/prusa-telemetry.jar.sha256
target/prusa_telemetry-0.1.0-SNAPSHOT.jar
target/prusa_telemetry-0.1.0-SNAPSHOT.jar.sha256
```

## Developer Install

Use this when you want REPL-driven development and hot reload.

```bash
git clone https://github.com/aeonik/prusa_telemetry.git
cd prusa_telemetry
bin/dev-service start
```

Open:

```text
http://localhost:9632
```

Useful commands:

```bash
bin/dev-service status
bin/dev-service repl
bin/dev-service cljs-repl
bin/dev-service logs
bin/dev-service stop
```
